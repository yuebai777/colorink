# Colorink v1.4.0 发布设计

## 目标

将当前工作区的功能改动整理为一个可验证的 Windows v1.4.0 发布：版本信息一致、首次启动易用、PyInstaller 双产物不缺少运行资源，并将源码和发布资产上传到现有 GitHub 仓库。

## 发布范围

- 纳入当前源码改动、新增的 CSP Companion、色空间模块、窗口高度逻辑、测试和更新日志。
- 版本字符串统一为应用 `1.4.0`，Windows 文件版本 `1.4.0.0`，Git tag 为 `v1.4.0`。
- 产出并检查 `Onedir` 与 `Onefile` 两种 PyInstaller 构建；GitHub Release 上传单文件 EXE，并保留目录版作为本地验证产物。
- 不提交 `build/`、`dist/`、`.reasonix/`、日志、缓存和其他生成文件。

## 首次启动默认值

首次启动（没有 `hotkey-config.json`）使用：

- 全局取色 `F11`；跟随鼠标 `Ctrl+R`；隐藏窗口 `Ctrl+H`；灰度滤镜 `Ctrl+G`。
- HSV 色彩空间模块，显示模块切换按钮；默认只显示 HSV 滑条和颜色历史，保持窗口紧凑。
- 历史色板 `8` 列 `2` 行；同步软件仍为 CSP，不自动启用 Companion 或开机自启。
- 保留 OKLCh 感知灰度、自动背景主题、100% UI 缩放和 6 倍取色放大。

已有配置通过现有的缺失键合并逻辑补齐新键，任何已有值都不覆盖。

## 实施与验证

1. 添加版本一致性和配置合并测试。
2. 更新 `core/updater.py`、`file_version_info.txt`、`release_notes.md` 和默认配置。
3. 检查两个 PyInstaller spec 对 Python 模块、原生 DLL、Overlay EXE、图标和 Qt 资源的收集；运行干净双构建。
4. 运行全部测试、导入检查、EXE 文件版本检查，并在可用环境启动构建产物做最小运行验证。
5. 检查 diff 和待提交文件后提交，创建 `v1.4.0` tag，推送代码和 tag，再创建 GitHub Release 上传单文件 EXE。

## 风险边界

- 构建必须在 Windows 依赖完整的环境执行；缺失 PyInstaller、C++ Overlay 或 GitHub CLI 时只报告阻塞，不伪造发布成功。
- GitHub 发布是外部副作用，但用户已明确要求上传；只使用现有 `origin`，不强推、不修改远程历史。
