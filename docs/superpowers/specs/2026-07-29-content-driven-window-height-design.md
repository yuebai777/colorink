# Content-Driven Window Height

## Goal

让 Colorink 主窗口根据当前实际显示的控件计算一个动态最小高度。滑块组、颜色历史网格和 LAB 亮度滑条的显隐或尺寸变化后，窗口高度跟随当前内容需求收缩或扩展。设置侧栏仍是主窗口上的覆盖层，不参与主窗口高度计算。

## Behavior

- 以主布局的实际 `sizeHint()`、滑块容器的实际 `sizeHint()` 和视觉区的最小尺寸计算所需高度。
- 视觉区的最小高度至少等于当前窗口可用宽度，保证按宽度绘制的色轮/色环和 LAB 方形不会被压扁。
- 更新 `QMainWindow` 的 `minimumHeight`，不使用按控件数量硬编码的高度表。
- 内容变高时立即扩展窗口，避免控件被裁切。
- 内容变低时同步收缩；用户手动拉大的高度只在内容需求未变化时保留，不能阻止控件显隐后的自动适配。
- `lockWindowSize` 仍只禁止用户手动拖动和 Ctrl+滚轮缩放，不禁止内容变化触发的必要自动扩展或收缩。
- 触发点包括启动完成、滑块显隐/排序刷新、模块切换、LAB 亮度滑条显隐、历史行数变化、界面缩放和主题/间距变化。
- 初始化时若窗口尚未显示，延迟到 Qt 完成首轮布局后再测量，避免使用尚未稳定的 `sizeHint()`。
- 调整过程需要防止 `resizeEvent()`、布局刷新和自动高度计算递归互相触发。
- 自动高度不改变窗口宽度、位置、DPI 换屏逻辑或设置侧栏几何位置。

## Design

`MainWindow` 增加一个小型的高度适配流程：

1. 若窗口尚未显示，使用单次 Qt 定时器延迟测量；显示后让 `sliders_layout` 和 `main_layout` 激活并根据当前可见控件重新计算几何。
2. 读取布局建议高度，并确保视觉区至少达到当前窗口可用宽度，同时包含标题栏和主布局边距。
3. 设置 `setMinimumHeight(required_height)`。
4. 记录本次自动高度。若控件显隐、历史行数或缩放导致内容需求变化，则把窗口高度调整为新的需求高度；只有内容需求未变化时才保留用户手动扩大过的高度。
5. 后续 `resizeEvent()` 只刷新内容几何，不重复触发会改变高度的自动流程，除非明确发生了内容结构变化。

所有触发点复用同一个方法，避免在设置、模块切换和布局刷新路径中产生分散的尺寸逻辑。

## Error Handling

不引入新的持久化字段或兼容分支。初始化阶段若布局尚未完成，方法只在 Qt 布局激活后执行；布局提供的建议尺寸作为唯一来源。自动调整使用重入标记，保证 DPI 适配和正常手动 resize 不被拦截。

## Testing

- 只显示一组滑块时，窗口最小高度随内容降低，且色轮/视觉区仍保持宽度驱动的完整高度。
- 打开多个滑块组、颜色历史或增加历史行数时，窗口最小高度增大且内容不被裁切。
- 切换 HSV/HLS/LCH 模块和 LAB 亮度条时，自动高度跟随当前可见控件。
- 用户手动把窗口拉高后减少控件，窗口不被强制缩回；再增加内容时仍能自动扩展到最低需求。
- `lockWindowSize` 开启时，用户手动 resize 仍被禁止，但内容变化仍能设置合理的最小高度。
- 界面缩放、主题间距和跨 DPI 屏幕移动不产生 resize 递归或尺寸漂移。
- 首次启动与切换色彩空间后的窗口高度一致，不依赖切换操作触发第二次布局测量。
